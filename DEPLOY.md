# Деплой на VPS

Стек: nginx (порт 80) → ASP.NET Core (порт 8080, внутри сети compose) → PostgreSQL 17.
Миграции применяются автоматически при старте приложения; фермы и их администраторы
создаются из переменных `FARM*_...` (см. раздел «Фермы»).

## Первый запуск на сервере

1. Установить Docker (включает compose-плагин):

   ```bash
   curl -fsSL https://get.docker.com | sh
   ```

2. Скопировать проект на сервер (например, в `/opt/salary-site`) любым способом:
   `git clone`, `scp` или rsync.

3. Создать файл `.env` рядом с `docker-compose.yml` по образцу `.env.example`
   и задать свои пароли.

4. Запустить:

   ```bash
   docker compose up -d --build
   ```

Приложение будет доступно на `http://<IP сервера>/`.

## Обновление

```bash
cd /opt/salary-site
git pull            # или заново скопировать файлы
docker compose up -d --build
```

## Полезные команды

```bash
docker compose ps                # статус контейнеров
docker compose logs -f webapp    # логи приложения
docker compose logs -f nginx     # логи nginx
docker compose down              # остановить (данные БД сохраняются в volume pgdata)
```

## Фермы

Каждая ферма — независимое хозяйство. Разделение идёт через учётные записи
администраторов: админ фермы видит и меняет только своих работников, технику,
справочники, журнал работ и учётные записи. Всё, что он создаёт, автоматически
относится к его ферме.

Фермы описываются в `.env` (переменные `FARM1_*`, `FARM2_*`, …) и создаются при
старте приложения. Учётная запись администратора создаётся, только если такого
логина ещё нет, — пароль в `.env` не перезаписывает уже изменённый пароль.
Название фермы, наоборот, обновляется из конфигурации при каждом запуске.

Чтобы добавить третью ферму, достаточно добавить в `.env` блок `FARM3_*`
(с новым уникальным `FARM3_ID`), продублировать в `docker-compose.yml` переменные
`Farms__2__*` и перезапустить `docker compose up -d`.

**`FARM*_ID` менять нельзя после первого запуска** — к нему привязаны все данные
фермы. Все данные, существовавшие до разделения по фермам, отнесены к
`11111111-1111-1111-1111-111111111111` (первая ферма).

Логины уникальны в пределах всей системы, а не фермы: при входе ферма определяется
по учётной записи.

## Данные

- База данных: volume `pgdata` (переживает пересборку и перезапуск).
- Аудит-логи приложения: volume `applogs` (`/app/logs` внутри контейнера).
- Выгрузка дампа на странице «Сервис» содержит данные только текущей фермы.

## HTTPS

Сейчас приложение отдаётся по HTTP (для доступа по IP сертификат выпустить нельзя).
Когда появится домен: направить A-запись на сервер, добавить в `nginx/nginx.conf`
server-блок с сертификатом (проще всего — certbot) и включить `Cookie:Secure=true`
через переменную окружения `Cookie__Secure=true` у сервиса `webapp`.
